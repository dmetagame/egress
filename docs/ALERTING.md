# Deterministic live alerting

Alerts are generated by ordinary code in `packages/risk-engine/src/live/alerts.ts`. AI/RWA interpretation remains upstream evidence; it does not generate free-form alerts and cannot choose transaction amounts.

## Alert inputs

The engine compares the previous archived canonical state with the current observation. It uses:

- Aave health factor, debt, collateral, and position scope;
- oracle adapter status and age;
- Uniswap active liquidity, executable state, and estimated slippage;
- OKX source revision/content hash and structured risk classification;
- snapshot integrity/status and block consistency;
- verified protocol configuration identity.

Each alert contains:

```text
alert type + severity
current snapshot hash + previous snapshot hash
block + timestamp
structured evidence { code, message, source, provenance[] }
previous state + current state
deduplication key
```

## Conditions

| Alert | Condition | Severity |
|---|---|---|
| `HEALTH_FACTOR_APPROACHING_TRIGGER` | HF moves downward into the configured 5% approach band above policy trigger | Warning |
| `HEALTH_FACTOR_DETERIORATED` | HF falls by at least 0.001 wad or 10 bps, whichever is larger | Warning |
| `ORACLE_APPROACHING_STALE` | Oracle age enters the configured 80% freshness band | Warning |
| `ORACLE_STALE` | Oracle adapter crosses its freshness limit | High |
| `LIQUIDITY_DETERIORATED` | Active liquidity falls by at least the configured 10% | High |
| `SLIPPAGE_DETERIORATED` | Estimated slippage rises by at least 25 bps | High |
| `SOURCE_CHANGED` | Official OKX revision/content hash changes | Info |
| `RISK_CHANGED` | Two usable complete risk classifications differ | Info/Warning/High/Critical based on new level |
| `SNAPSHOT_UNAVAILABLE` | Current observation leaves `COMPLETE` | High or Warning |
| `SNAPSHOT_INTEGRITY_FAILURE` | Claimed snapshot hash fails canonical validation | Critical |
| `POSITION_UNAVAILABLE` | Previously readable position can no longer be read | High |
| `POSITION_CLOSED` | One supported position leg reaches zero | High |
| `DEBT_INCREASED` | xETH debt rises by at least 0.01 xETH or 5 bps, whichever is larger | Warning |
| `COLLATERAL_REDUCED` | xBETH collateral decreases | Warning |
| `POSITION_SCOPE_CHANGED` | Asset identity or isolated-market scope changes | Critical |
| `PROTOCOL_CONFIGURATION_CHANGED` | Verified protocol identity/configuration hash changes | Critical |

The thresholds are explicit and testable. They are not inferred by an LLM. Alert severity does not authorize execution.

## Deduplication and transitions

Alert keys include alert type, severity, current snapshot hash, previous snapshot hash, and the relevant previous/current state. Repeating the same polling state cannot create a duplicate alert. A later independent transition has different state identifiers and can alert again.

`SOURCE_CHANGED` and `RISK_CHANGED` are intentionally separate. A wording, formatting, or operational source revision can be recorded without changing risk classification. Unsupported or unavailable evidence produces no confident risk transition.

Alert thresholds are versioned. Policy version 1 suppresses sub-threshold debt accrual and immaterial health-factor movement while preserving material deterioration and trigger crossings. The version is stored on each alert and included in its deterministic deduplication identity, so a replay can reproduce why an alert was emitted or suppressed.

## Failure behavior

Unavailable, stale, invalid, inconsistent, or missing observations remain explicitly non-usable. The alert engine may emit an operational alert, but it never changes the state to `LOW`, `NORMAL`, or protected. A previous successful snapshot remains history only.

Persisted alerts are delivered through the Phase 8C sink abstraction after archive insertion. Delivery failures degrade operations but cannot alter the archived risk decision or create a transaction.

## Operational example

The Phase 8B live poller produced a real read-only transition on X Layer mainnet:

```text
block 68053231 -> 68053277
DEBT_INCREASED
HEALTH_FACTOR_DETERIORATED
```

The debt increase was supported by the Aave pool/position provenance and the health-factor change was supported by the same account read. No transaction was created or submitted.
